# 三人聚智遥控：局域网聊天版

手机应用包名 `com.sanrenjz.tools.remote`，当前版本 1.6.0（versionCode 7）；Android 8 及以上。电脑端功能在 `codex/mobile-remote-control` 独立工作树中基于 `f0e2aef` 开发，集成时保留 main 已有功能与私有插件边界。

Android 源码已独立迁到 `D:\wenjian\python\develop\Android\sanrenjz-tools-remote`；桌面仓库不再维护 Android 源码副本。构建与可分发发布 APK 的位置见 [Android 项目与分发](android-project.md)。

插件 1.7.1 增加 Windows 连接权限检查和修复。Windows 规则同时匹配程序路径、端口及网络类别；从旧工作树切到 main 目录启动，可能由原路径可用变为新路径被阻止。插件只为当前程序维护当前 TCP 端口与 UDP 19875，来源限制 LocalSubnet；不会关闭防火墙或修改用户既有规则。首次显式修复可能需要 Windows 提权授权，之后日常使用不要求管理员运行。规则状态不等同于手机实际可达或配对成功，应分别核验跨设备 TCP 与实际配对。过期二维码须重新生成和扫描。

## 使用方式

1. 手机与电脑连接同一个局域网。启动本分支的电脑主程序，打开独立安装的“媒体投放接收器”插件，进入“连接手机”启用局域网遥控并应用设置。默认端口为 TCP 19876；自动发现使用 UDP 19875。主程序设置已移除手机遥控页，底层连接基础仍由宿主提供。
2. 在插件内选择手机可达的局域网网卡地址并生成二维码，手机在“我的 → 连接电脑”扫码。Android 1.5.0 使用专用竖屏相机页。二维码两分钟有效且只能配对一次；首次配对后保存电脑证书指纹和设备身份。插件内可以刷新状态并撤销配对，撤销需再次确认。
3. 手机聊天输入任务。手机只提交文字、明确选择的附件和已登记业务操作；插件核心、文件处理和 AI Runtime 都在电脑执行，结果返回聊天页。
4. “工具”页先显示六个分类，进入分类后才展示具体接口。账号登录、供应商认证、系统提权及尚无业务接口的插件继续在电脑操作。
5. 电脑可以撤销手机配对。关闭遥控服务或退出主程序会断开连接。手机重连恢复状态，不自动重发模型请求或已提交的文件操作。

首次使用时允许 Windows 防火墙中的局域网访问。开发机的防火墙规则只适用于该开发路径；其他用户需允许其实际安装路径。多网卡时可在配对信息内选择可达的私有 IPv4 地址；不支持公网地址、域名中继或 IPv6。

## 界面与执行范围

- 聊天：任务、执行状态、结果、图片预览、复制、下载、取消和需确认的操作；当前回复和历史均支持 Markdown 标题、列表、表格、代码块、引用和链接，经过 DOMPurify 白名单净化。手机图标与桌面主程序共用 `build/icon.png`。
- 工具：文本与数据、编码与安全、文件与文档、图片与二维码、时间与计算、AI 助手六类。插件清单另外显示已接入/暂需电脑界面操作。
- 投放：以视频 App 自带的 DLNA 投屏为主要入口，另设手机屏幕镜像；本地媒体和链接队列放在折叠区域。
- 我的：局域网连接、电脑现有模型、配对权限。历史、连接详情和每个工具分类均为独立页面。

当前登记 27 个业务接口，复用已有插件核心或共享 Runtime。这不等于 41 个原有插件的每项功能都已远程化。AI 不会任意点击电脑窗口、运行任意 JavaScript、IPC 或系统命令；没有可调用接口时必须说明限制。自然语言任务一般先由电脑模型规划；明确的 UUID、JSON 格式化任务可离线执行。

文档总结先调用文档读取接口，再将文字交给电脑已有模型；扫描 PDF 不含 OCR，大文档的模型上下文会明确截断。图片附件当前可转换、调整大小和下载，尚未接入通用视觉问答。手机麦克风可手动录音并上传，尚未提供自动语音转写接口。每次上传上限 512MB；上传与生成文件保存在电脑 userData 的 `remote-control/received` 与 `exports` 下，不会自动清理用户文件。

## 媒体投放

媒体投放接收器自 1.3.1 起单独作为可选 ZIP 插件分发，主程序安装包排除此插件全部资源。主程序只保留轻量安装发现、受限 IPC 接入和已配对连接；运行组件、镜像、播放器、选集及输入业务在插件目录。首次需要升级到支持可选加载的主程序预览版；之后可通过本地插件导入单独安装或更新。未安装不启动投放进程，卸载清理自身进程，不影响手机聊天。手机 APK 仍是单独安装的应用。

电脑插件 1.7.0 分成连接手机、AI 操控、手机镜像、视频投放、播放队列、设置六个页面，AI 操控仍位于手机镜像左侧。镜像画面占据主要空间，底部保留授权状态、手机操作及画面全屏；视频在插件内部播放，队列页独立添加电脑文件或链接。`node scripts/build-cast-plugin.js` 生成包含固定上游运行包与许可证的独立 ZIP。已有插件覆盖更新后须重启正在运行的主程序，以加载新后台模块；扫码修复及自动坐标操作需更新手机 APK 为 1.6.0，移除主程序旧设置页需使用本次 connection-preview 主程序。

使用独立的 Macast 0.7 官方 Windows 运行包及其内置 mpv 0.34.0，无需用户安装 Python。构建源码前运行 `powershell -File scripts/prepare-cast-runtime.ps1` 下载固定发行包并校验 SHA256。官方源：[Macast v0.7](https://github.com/xfangfang/Macast/releases/tag/v0.7)，[mpv 0.34.0 源码及版权说明](https://github.com/mpv-player/mpv/tree/v0.34.0)。上游许可证保存在插件 `THIRD_PARTY_LICENSES`；应用通过独立进程和固定协议控制它。

开启接收后，即使关闭插件管理页面仍能接收；主程序退出时只清理自身启动的进程。服务启用设置会持久化，后续随主程序启动。DLNA 不具备设备配对，运行在可信局域网；其监听地址和设备发现由上游 Macast 实现。不要给接收端配置公网端口映射。

手机视频 App 使用自己的“投屏”按钮，选择实际显示的设备名，例如 `Macast(miniPC)`。电脑在接收插件的播放区显示视频，mpv 不另开小窗口。视频由电脑播放，手机可回到桌面或其他应用。接收窗口重开及新媒体到达时保留已有窗口位置，避免切换集数时重新移动到其他显示器。播放区全屏只显示视频，按 Esc 恢复插件布局；切换到其他页面时隐藏原生画面，避免覆盖操作。

视频底部的进度条显示播放器实际位置和总时长，点击或拖动松开后跳到所选时间；全屏时仍位于视频下方，不被原生画面遮盖。跳转保留暂停及倍速，切换媒体后旧请求失效；拖动途中不逐次发送命令。直播、时长未知或不可跳转的媒体禁用滑块并显示原因；缓存受限源只保证其实际可跳转部分。源码逻辑、真实本地视频鼠标点击/拖动/回退/全屏，以及手机正在提供的局域网 HTTP 视频流跳转已验证；该手机流不是已确认的腾讯源，腾讯新版进度兼容性未单独复测。

视频播放栏增加 0.5、0.75、1、1.25、1.5、1.75、2、2.5、3 倍速度。插件通过 mpv IPC 设置并回读实际 `speed`，没有媒体或真实输出未就绪时禁用；设置失败恢复上一速度。固定 mpv 0.34.0 的真实本地视频及腾讯当前投放样本均验证 2 倍会加快播放进度；腾讯样本在 1.2 秒内前进约 2.27 秒，测试后恢复原暂停、1 倍及音量。电脑倍速独立于手机 App 的倍速入口；直播或受限源不保证支持。依据：[固定版本 mpv 参数](https://github.com/mpv-player/mpv/blob/v0.34.0/DOCS/man/options.rst)。

电脑的“选集 / 播放列表”支持点选本应用提供的明确媒体队列。腾讯视频 9.04.55 的本次真实会话只提供当前媒体资源，未提供完整剧集列表或 NextURI，因此不支持在电脑列出其全部集数；不能凭一个视频地址生成其他集数。

明确队列的续播由所属 mpv 的 `end-file / eof` 事件触发，暂停、手动停止和外部媒体切换不会冒充当前队列结束。腾讯 App 的自动下一集仍待完整验收，不能承诺 App 必定推送下一项。

没有投屏入口的 App（例如用户所述红果页面）可尝试手机镜像：在遥控 App 中点击“开始镜像”，接受 Android 系统屏幕共享授权，电脑接收窗口显示当前手机画面。镜像经已配对的局域网 WSS 传输 JPEG，最长边 1280、最多 8 帧/秒，适合展示操作；不作为高清视频播放替代方案。手机切换页面时镜像也会变化，不能保证红果后台播放而手机独立操作。可选应用音频采用 Android 10+ AudioPlaybackCapture，受源 App 策略限制，当前尚未完成真机有声镜像验收。受保护内容可能黑屏或无声，不能绕过限制。

普通用户的聊天、媒体投放和镜像均通过局域网，无需 USB 数据线、ADB 或 USB 调试。开发安装与调试使用 USB 不代表应用的数据传输方式。

## 电脑操作手机与画面全屏

在手机“投放 → 手机屏幕镜像”点击“设置辅助功能权限”，由用户在 Android 设置中开启“三人聚智遥控 · 电脑操作手机”。随后勾选“允许电脑操作手机”，再开始镜像。权限与本次会话开关必须同时启用；开关默认关闭。结束镜像、撤销电脑配对或断开局域网连接后，控制立即失效。

电脑可点击、拖动、用滚轮滑动，以及通过输入法提交中文文本；可使用返回、主页按钮。文字输入只操作当前可编辑的辅助功能节点，密码字段不写入。部分应用的自绘输入框、受保护界面或系统授权页面可能不支持这些操作，不能保证所有手机应用可完整控制。

“全屏手机画面”只将画面区域设为全屏，插件工具栏、播放列表和其他面板隐藏，画面按手机比例缩放；点击黑边不会发送手机操作。按 Esc 返回接收窗口。视频页的全屏也在同一插件内部完成。

## AI 操控手机

手机 App 升级至 1.6.0 后，开启镜像和当次操作授权，在电脑插件的“AI 操控”输入任务并选择电脑已配置的模型（OpenCode CLI、Codex CLI 或共享 AI Runtime）。默认通过本机 OpenCode CLI 处理，复用其已连接供应商目录与认证，并可附带镜像 JPEG（需要视觉模型）；关闭截图则只提交当前可见控件。识别方式中保留“电脑 AI · 可访问控件”和“电脑 AI · 识屏＋控件”，使用原有共享 Runtime。开始前需同意将当前观察交给所选 AI 供应商；手机不存储模型凭据，不加载模型。控件来自 Android 官方辅助功能接口：[AccessibilityService](https://developer.android.com/reference/android/accessibilityservice/AccessibilityService)。

CLI 检测、自定义路径、截图开关和教程位于本插件顶部“设置”菜单，提供官方 npm 安装、版本检查及 `opencode auth login` 提示。缺失或认证不可用会显示原因，用户可明确改用电脑 AI；不会自动重装现有 CLI。配置和模型选择持久化在插件 userData 的 `cast-receiver/phone-ai.json`，不保存供应商凭据。插件使用现有 `OpenCodeRuntime` 只读模块启动独立的 `127.0.0.1` 服务，随机端口和随机 Basic 认证，不连接外部 OpenCode 地址。每次只请求一个登记的手机动作；CLI 隔离配置禁用电脑命令、文件、MCP 和外部 Skill；退出/卸载停止自有 CLI 子进程，闲置两分钟自动停止。CLI 二进制不捆绑到插件或主程序。文档：[CLI](https://opencode.ai/docs/cli/)、[Server](https://opencode.ai/docs/server/)。

1.7.0 新增本机 Codex CLI 可选模式，采用官方 `app-server --listen stdio://` 与临时线程，模型来自当前 CLI `model/list`，凭据由 CLI 管理。独立子进程使用只读沙箱，并关闭命令、浏览器、插件、协作等工具；用户 MCP 配置会被合并，必须针对当前全部 MCP 名称在临时线程中逐个设为禁用，不能仅用空表覆盖。真实 0.158.0 的三个 MCP 均报告 disabled、工具及资源数为 0。请求取消、超时、协议异常和卸载有明确清理，闲置两分钟结束自有服务。资料：[Codex App Server](https://developers.openai.com/codex/app-server/)。本功能不修改主程序、共享 Runtime 或根依赖，不捆绑 CLI，手机仍使用 1.6.0。

模型选择在变更时立即持久化，按 OpenCode、Codex、可访问控件、识屏＋控件分别保存；关闭重开及方式切换恢复，上次模型临时不可用时保留记录并禁用任务，刷新或用户选择其他模型后恢复。旧 1.6.0 单个 OpenCode 选择迁移，不覆盖原端口、设备身份或供应商认证。安装面板移入设置后，AI 页仅保留任务与流程；标题/说明缩为 14px/10px，小尺寸继续压缩；流程跟随新步骤，用户查看旧记录时保留滚动位置。

实现按“观察 → 电脑模型选择一步 → 校验 → 手机执行 → 重新观察”循环，最多 24 步。参考了 [Open-AutoGLM](https://github.com/zai-org/Open-AutoGLM) 的逐步识屏方式，但采用本应用既有局域网连接与辅助功能权限，不引入其 ADB/HDC、Python 或模型运行包。操作只支持打开已登记的手机应用、点击可见节点、替换可编辑文本、受限手势和返回/主页等；不接受任意脚本、命令或文件路径。

普通打开应用、搜索、选择结果、无文字控件、坐标点击、滑动和播放自动判断执行；发送、发布、删除、付款会停在确认区，显示任务与本步目标。点击和填字核对当前应用、目标控件的身份、文字和位置，其他推荐或进度变化不影响稳定目标；坐标手势还需核对整页快照。目标变化而手机明确拒绝、尚未执行时，最多重新观察三次并让模型重新规划；不重放旧动作。超时等结果不明、取消、权限撤销、断线或显式关闭接收页不自动重放。模型 `done` 必须引用当前可见控件作为依据，界面仍标注“AI 判断已完成，请核对手机”，不能据此认定目标语义或外部发送已经真实成功。

微信内部数据库、完整聊天历史和其他应用私有文件不在实现范围内。普通 Android 应用受 [应用沙箱](https://source.android.com/docs/security/app-sandbox) 限制；插件只能读取当前屏幕及可访问控件。密码字段不读取或写入，应用未提供节点或系统禁止捕获时需要用户处理，不能保证任意 App 全自动操作。插件不持久化观察画面或节点；AI 任务动作摘要仅保留在当前页面。

本次还修复宿主失焦后三分钟自动关闭接收页的情况：插件使用既有 `minimizePlugin(...,{keepAlive:true})` 登记持续会话，并关闭自身页面后台限速；真实接收页隐藏 324 秒后仍是同一窗口，并新增 381 帧。钉住的窗口不隐式隐藏；用户显式关闭接收页仍结束手机控制及 AI 任务。每个页面实例使用独立模型请求 ID，避免延迟取消影响重开后的任务。本次速度与 AI 功能未新增主程序代码或依赖。

## 公网删除与回滚

本版本不包含公网开关、信令服务、TURN、中继地址和域名部署脚本。此次创建的公网 DNS 记录、信令进程及其服务目录、独立 Nginx 站点、HTTPS 证书与续期钩子已经撤除；服务器原有 Nginx 保持正常。没有部署 coturn。

本功能不自动推送或触发 Release。回滚时先在插件“连接手机”关闭局域网服务和投放接收，再退出程序；本地合并可通过 `git revert -m 1 <本次合并提交>` 撤销，或安装原版本。手机可解除配对或卸载独立 App。Android 源码与发布签名独立于桌面仓库，不随桌面代码回滚删除。
